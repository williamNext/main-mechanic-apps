<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mobile client → HTTP API | Fully untrusted JSON bodies cross here; the three Expo apps are separate repos this server cannot vouch for |
| process environment → server | JWT_SECRET and DB_PATH enter here; a weak or defaulted secret compromises every session |
| application code → SQLite file | All persistence crosses here; the file is the sole source of truth and has no separate access-control layer |
| npm registry → developer machine | Native addons (`better-sqlite3`, `argon2`) execute build scripts at install time |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Spoofing | `src/auth/jwt.ts` verifyAccessToken | high | mitigate | Pin the verification algorithms option to the single-element HS256 list so a token declaring `alg: none` or an asymmetric algorithm is rejected rather than trusted |
